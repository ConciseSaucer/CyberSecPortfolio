Reconnaissance

Physical Access

During the initial assessment, I gained physical access to the machine using a guest account. The machine's configuration permitted free navigation through the file system, with the exception being the /home directory. I checked file permissions and quickly accessed the /etc/shadow file, which contains password hashes.

Hash Analysis

Upon obtaining the hash, I consulted ChatGPT to identify the hashing algorithm. The hash was determined to be a SHA512 hash, denoted by the $6$ prefix. Using John the Ripper on Kali Linux, I initiated a password cracking attempt.

Network Scanning

While the password cracking attempt was running, I proceeded to perform network reconnaissance using Nmap on a Raspberry Pi. The VM was on a bridged adapter, and the Raspberry Pi allowed for discreet network analysis (It was cool).

  1. Network Sweep: Conducted a network sweep to identify live hosts and detect the vulnerable machine by matching its MAC address to VirtualBox.

  2. Version Detection: Performed a detailed service version scan on the identified machine, revealing an outdated FTP service (ProFTPD 1.3.3c).

Exploitation

Attempted Exploits

Initially, I attempted to exploit the ProFTPD vulnerability using the Metasploit framework but was unsuccessful in establishing a session.

Successful Exploit

I then used a Python script specifically designed to exploit the backdoor in ProFTPD 1.3.3c. After providing the appropriate IP addresses for the local and target machines, the script successfully spawned a root shell.

Post-Exploitation

Following the successful exploitation, I ended the password cracking attempt due to the complexity(length) of the password. However, I conducted a manual password guessing attack on the marlinspike user account. After a few attempts, I successfully logged in with marlinspike as the password.

Using the acquired credentials, I established an SSH connection and escalated privileges using sudo su, gaining a remote root shell.

Recommendations for Prevention

To mitigate similar attacks in the future, I recommend implementing the following security measures:

  1. File Permission Management:

    • Restrict read access to sensitive files like /etc/shadow.

  2. Software Updates:

    • Regularly update and patch services, particularly externally accessible ones.

  3. Strong Passwords:

    • Enforce the use of complex passwords and implement account lockout policies.

These measures would significantly reduce the risk of unauthorized access and system compromise.
